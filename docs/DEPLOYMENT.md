# Deployment

The function runs on AWS Lambda in `eu-central-1`, behind a Function URL. Everything it needs is declared in the OpenTofu stack in `infra/`, and GitHub Actions applies it — there is nothing to click and nothing to deploy by hand.

## What the stack holds

- The Lambda `osm-provider` on `nodejs24.x` and `arm64`, with 512 MB and a 300 s timeout, running `lambda.handler` from `dist.zip`.
- A Function URL with auth type `NONE`. The function checks the bearer secret itself, before it routes or spends an Overpass query.
- The secret, generated by `random_password` and handed to the function as `OSM_FUNCTION_SECRET`.
- The log group `/aws/lambda/osm-provider`, kept for 7 days.
- The execution role at the IAM path `/osm-provider/`, carrying the workload permission boundary read from `/mypreflight/bootstrap/workload-boundary-arn`.
- Two SSM parameters for `flight-tracker-api` to read: `/mypreflight/osm-provider/url` and `/mypreflight/osm-provider/secret`.

State lives in the `mypreflight-infra` bucket under `osm-provider/terraform.tfstate`, encrypted with the `alias/mypreflight-state-key` KMS key.

## How a change ships

1. A pull request runs `integrity`: the checks in Docker, then `./zip.sh` and `dflook/tofu-plan`, which comments the plan on the pull request.
2. Merging to `main` runs `release`: it tags the version from `package.json`, creates the GitHub release, builds `dist.zip` again and applies the stack with `dflook/tofu-apply` in the `production` environment.

`./zip.sh` builds the bundle in Docker — `npm run bundle`, esbuild folding `src/lambda.ts` into one `lambda.js` — and zips it with fixed timestamps, so an unchanged source gives an unchanged zip and no redeploy.

## Checking a deployment

With credentials for the account the function runs in:

```shell
URL=$(aws ssm get-parameter --name /mypreflight/osm-provider/url --query Parameter.Value --output text)
SECRET=$(aws ssm get-parameter --name /mypreflight/osm-provider/secret --with-decryption \
  --query Parameter.Value --output text)

curl -i -H "Authorization: Bearer $SECRET" "$URL/pull?icao=LIPZ"
```

- `200` with an `airport` object — done.
- `401` with `UNAUTHORIZED` — the token does not match the secret the function was deployed with.
- `404` with `NOT_FOUND` — the path is wrong; the function serves `/pull` only.
- A slow first answer — the first request is a cold start plus a live Overpass query. Retry once before suspecting anything; a large hub takes tens of seconds.

```shell
aws logs tail /aws/lambda/osm-provider --follow
```

## Notes on Lambda

Measured or taken from the docs, not guessed:

- **The default Lambda timeout is 3 s**, nowhere near enough. `infra/lambda.tf` sets 5 minutes explicitly. The client's retry budget is sized to fit inside it, and `client.spec.ts` asserts that against `infra/lambda.tf` — so if you lower one, the suite tells you.
- **A Function URL response is capped at 6 MB**, and the body travels inside it as an escaped JSON string. The handler refuses anything over 5 MB with a `413` rather than letting the invocation fail with an opaque error.
- **Node 24 is the runtime.** Keep `runtime` in `infra/lambda.tf`, the Dockerfile, `@types/node`, the esbuild `--target` and the `tsconfig` target aligned with it.
